# Doxa Playground

A mobile browser experiment for Doxa epistemics. The app and data are committed in this repository; no backend, account, API key or build step is required.

## Use on a phone or iPad

Choose a scenario or tap **Nächstes Szenario**. Seven examples are embedded in the HTML. An additional scenario is loaded from the relative file **[scenarios.json](scenarios.json)**. Add further entries there to make new experiments selectable without rewriting the app. Changes may be delayed by hosting caches.

Each catalog entry has `id`, `title`, optional `description`, `query`, and `data`. The data object contains `facts` and `rules` arrays. A new catalog entry must have a unique ID. Examples in the catalog do not override embedded IDs.

JSON editing is optional and collapsed by default. The app supports importing and exporting a single experiment:

```json
{
  "data": {
    "facts": [{"name":"a:x","b":0.8,"d":0,"root":"observation"}],
    "rules": [{"name":"a-b","premises":["a:x"],"consequence":"b:x","b":0.9,"d":0}]
  },
  "query": "b:x",
  "profile": "productmax"
}
```

The textarea takes only the `data` object. File import takes the complete envelope above. Experimental inputs are saved locally when browser storage is available, not synced between devices. Export important experiments. Do not put confidential data in this public repository or enter secrets on a third-party preview origin.

## Experimental scope

This is **not a Doxa reference implementation**. It implements finite ground propositions and acyclic positive-premise rules, not the full DSL, variables, defaults/specificity, negative premises, recursion, ledger, authorization, ingestion, identity resolution or temporal filtering.

Support and disbelief remain separate. Premise disbelief weakens applicability without creating disbelief in the conclusion. Rule `d` contributes disbelief to its conclusion. An independent direct observation is not weakened by conflict in another derivation.

Profiles are provisional indicators, not probabilities:

- `minmax`: each supporting proof is penalized by `(1 - premise.d)^2`; required proofs and the rule channel combine by minimum.
- `productmax`: source/channel factors and per-proposition conflict factors are unioned before multiplication. Shared factors count once: the diamond example returns 0.8, not 0.64.
- `netminmax`: each supporting proof uses `max(0, proof.b - premise.d) * (1 - premise.d)`; required contributions combine by minimum.

All three aggregate alternative same-channel evidence by maximum. A profile applies to an entire evaluation; switching recomputes the experiment. Conflict factors are keyed by proposition, not a complete evidential-dependence calculus. Reused explicit roots must have consistent b/d values. An omitted root is generated by array position; use explicit roots for portable, stable evidence identities. Omitted b/d default to 1/0; weights outside [0,1] are rejected.

Explanations show immediate rules and transitive supporting origins, not a complete Doxa proof graph or full opposing-evidence ancestry. Cycles, invalid input, excess proof combinations and detected product underflow produce errors, not definitive negative answers.

## Verification

Run **`node --test tests.cjs`** with Node.js 22. No dependency installation is necessary. All **36 tests passed** when preparing this publication. These cover propagation, shared origins, order independence, conflict handling, validation, UI handlers, storage failures and restoration. UI unit tests use a DOM double.

Additional local Chromium checks used a 390×844 touch-emulated viewport: all eight scenarios across three profiles, scenario selection, the Next button, the 0.8 diamond result, the 0.72 chain result, no JavaScript errors and no horizontal overflow passed. This check rendered the document in memory and mocked the scenario fetch; it is **not a live hosting test or a real iPhone/Safari test**.
